# 贡献范围与参与方式

[English](contributions.md) · [首页](../README_zh.md) · [仓库流程](../CONTRIBUTING.zh-CN.md)

## 职责归属

Julius 负责实验设计、产品架构设计与模型架构设计。一线编码、部署和实验执行是团队实施流程中的其他职责。个人展示应准确命名角色，避免使读者误认为完整系统由一人独立实现。

公开版本包含团队授权的原创源码、文档和精选结果，第三方组件保留原声明。添加姓名与单位前应取得许可，并写明具体工作。

## 第一次贡献

从[证据说明](../evidence/README_zh.md)选择一行，阅读 JSON 与研究案例，核对端点、比较方向、样本单位和数值。创建 Issue，提供字段路径及修改建议或核对结论。修改文档时同步两种语言，提交 PR 并附下方记录。维护者对照来源审阅，通过后合并并登记结果。

| 任务 | 交付物 | 验收 | 认领状态 |
|---|---|---|---|
| 证据复核 | 下方格式的 Issue/PR 记录 | 字段、单位、运算与边界完整 | 开放；通过 Issue 认领 |
| 全新 mock 安装 | 环境与命令记录 | Linux/WSL2 版本、锁文件安装、测试和一个 mock 任务 | 开放；通过 Issue 认领 |
| 目标函数解释 | 案例 01 与 Notebook 01 改进 | 三种目标约定一致，示例通过 | 开放；通过 Issue 认领 |
| 产品算法适配图 | 关联源码的说明与 mock 输入 | 输入输出映射和未支持字段有测试 | 开放；通过 Issue 认领 |

## 贡献记录模板

```markdown
### 问题与范围
检查的结论或行为：
### 角色
实验设计 / 架构 / 实现 / 执行 / 审阅 / 文档：
### 输入与来源
仓库提交：
文件字段或原文位置：
数据权利 / 合成输入：
### 方法
系统与运行时：
命令与模式（mock / 本地 / 外部）：
比较、样本单位与容差：
### 结果
预期：
观察：
输出哈希或公开产物：
限制与失败步骤：
### 审阅与登记
Issue 与 PR：
审阅者与结论：
已更新的状态 / 证据文档：
```

## 维护与交接

双语同步维护，证据转换可追溯，历史结果与新执行分别登记。交接提供 Issue、分支、已完成检查和下一步。外部执行修改需要审阅模式、权限边界与费用动作。上游更新记录版本并保留许可。
