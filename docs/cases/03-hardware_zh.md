# 案例 03 · 解释理想线路与真实硬件的差距

[English](03-hardware.md) · [研究地图](../research_zh.md) · [Notebook](../../notebooks/03_hardware_transfer.ipynb)

## 配对问题

硬件结果需要绑定逻辑线路、参数、物理映射、测量顺序、shots 和设备校准才能解释。设备标称寄存器大小不能代表具体实验规模或质量。本研究在天衍287平台上使用六比特线路。

归档迁移研究包含 500 条局部消息线路和 500 条 QAOA 线路，每条测量 1,024 次，真实硬件覆盖共 1,024,000 shots。配对云端含噪模拟返回 999 条有效线路和 1 条终态失败，共 1,022,976 次有效测量。相应比较使用 999 条配对硬件记录，不能把两边都写成 1,000 条。

## 五种分布回答不同问题

| 分布 | 固定内容 | 变化内容 |
|---|---|---|
| 理想状态向量 | 冻结的编译任务与参数 | 精确概率参照 |
| 理想有限测量 | 同一理想概率 | 按记录测量数产生抽样 |
| 本地含噪模型 | 已登记噪声假设 | 不执行设备的通道演化 |
| 云端含噪模型 | 配对提交线路 | 服务方实现和有限测量 |
| 真实硬件 | 已提交物理线路及映射 | 观测校准下的设备行为 |

归一化分布 $p,q$ 的总变差为 $\mathrm{TV}(p,q)=\frac12\sum_x|p(x)-q(x)|$。Hellinger 距离为 $H(p,q)=\sqrt{\frac12\sum_x(\sqrt{p(x)}-\sqrt{q(x)})^2}$。公开表格区分 $H$ 与 $H^2$。三持仓约束的可行率，是恰好包含三个 1 的位串概率之和；只找到一个最优样本不能描述完整分布。

## 归档观察

| 指标，按线路族平均 | 消息线路（500 条硬件） | QAOA（500 条硬件） |
|---|---:|---:|
| 编译深度 | 48.00 | 419.08 |
| 双比特门 | 29.00 | 179.88 |
| 硬件与理想 TV | 0.16652 | 0.88700 |
| 硬件与本地含噪 TV | 0.15623 | 0.23501 |

QAOA 族的硬件可行率约为 **31.51%**，理想参照为 **100%**，本地含噪模型为 **35.22%**。更大的编译深度与双比特操作量提示需要分析噪声，但仅凭该表不能建立深度的因果效应。

[硬件表](../../evidence/hardware-per-circuit.csv)保留全部 1,000 行；[云端表](../../evidence/cloud-per-circuit.csv)保留 999 条配对记录，其中 QAOA 为 499 条。这 499 条的均值与完整 500 条硬件汇总略有差别，引用前必须先确定总体。

## 统计范围与来源

归档只有一个已观测硬件校准快照。2,000 次 bootstrap 在线路族内按原始五线路提交区组重采样。得到的是该线路集合与校准条件下的描述性区间；提交批次不等于独立设备校准。

原始记录保留请求/回执来源与计数对账。本公开版本提供筛选数值字段和原汇总 SHA-256；服务方句柄及内部执行元数据保留在源档案。归档的[独立数值实现检查](../../evidence/independent-numerical-check.json)报告差异低于 `1e-11`，实际最大值约 `5.6e-16`。它是在同一分析任务中的第二套实现，不是外部团队复现。

Notebook 和[公开证据检查器](../../tools/verify_public_evidence.py)独立汇总公开行，不查询设备，也不重新生成服务方回执。当前档案范围见[复现状态](../status_zh.md)。
